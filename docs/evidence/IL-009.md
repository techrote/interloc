# IL-009 — bounded retention and privacy recovery

## Objective
Implement issue #10's local quotas, pending-evidence protection, restart-safe
expiry, backpressure and privacy recovery without destructive remote cleanup.

## Implemented scope
Owned UUID-addressed local store, byte/object/pending/catalog ceilings, protected
pending data, age and explicit expiry, digest-checked reads, crash-recoverable
write/deletion intents, stable backpressure/gap states, bounded incident inventory,
reviewed offline pending-request cancellation and inert mailbox/epoch review.

Unknown files/links/ownership changes stop cleanup. Artifact tombstones and broker
request replay records are never silently evicted to make room. Disk failure that
prevents recording its own error still sets an in-memory failure gate. The store
is single-owner; its explicit short SQLite transactions are separate from broker
state and do not change that component's schema.

## Non-goals

capture, automatic Chat send, raw-log export, credential action, native power-cut
proof, force-push or remote branch/history deletion. Local artifact retention does
not erase third-party copies. No dependency on unmerged IL-008 internals.

## Security review
No subprocess, network or credential read is introduced. Generated UUID paths
stay inside an explicitly created/verified store. Retention descriptors contain
no raw payload or absolute paths and do not claim sanitation or permission to
publish. Offline revocation requires stopped local writers, exact review digest,
and the broker owner lock; possible started effects require reconciliation.
Same-account OS compromise and hardware flush behavior remain stated limitations.
