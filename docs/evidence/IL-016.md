## Implemented scope

Five exact read capabilities: `github.issue.read`, `github.issues.list`,
`github.pr.read`, `github.checks.read`, and `git.worktree.status`. Their argument
schemas reject arbitrary endpoints, hostnames, executable/command strings,
paths, environments and extra fields. Existing mailbox policy still applies;
separate project/worktree mappings and exact capability grants are additionally
required. The adapter is disabled by default and does not self-register.

GitHub reads use bounded fixed-host GETs, selected response fields, explicit
one-page results, numeric repository/object checks, pre/post visibility and
local-authority validation, deadline/cancellation checks, and sanitized evidence
objects. Check-run records are not an aggregate pass or a merge decision.

Native execution drains bounded stdout/stderr concurrently and terminates the
process group or Windows Job Object on cancellation, timeout or overflow.
Worktree status uses disposable Git metadata and an index copy, not the target's
config, helpers, filters, hooks or index writes. Enrolled directory identity is
verified from filesystem identifiers after rejecting unsafe/link/reparse paths.

## Security review

| Boundary | Retained tests |
|---|---|
| Separate project and mailbox authority | Disabled default, absent project, absent grant, wrong origin/device/scope, exact capability mapping |
| Consent and current authority | Confirmation digest/target binding, revoked/stale approval, policy change, disable and expiry between API calls |
| Remote argument/input boundary | Unknown fields/capabilities, bool/integer bounds, full SHA, endpoint/host/argv/path injection, duplicate/deep JSON |
| Correct destination/result | Numeric repo ID/full name/visibility checked before and after; issue number/URL and check-run SHA checked; failed data discarded |
| Native subprocess lifetime/privacy | Concurrent floods, cancellation, timeout, descendant holding pipe, absent/batch/relative executable, credential/injection environment |
| Git target integrity | Config/filters/fsmonitor/hooks/includes inert, copied index, all synthetic file hashes unchanged, split-index/alternates refused, HEAD/index/file changes discarded |
| Filesystem boundary | No symlinks/junctions/FIFOs/UNC/ADS, bounded metadata inventories, OS-proven directory identity rather than string matching |
| Export privacy/integrity | Redact before JSON escaping, token split by ANSI, personal paths/OSC stripped, exact exported byte/hash assertions |

The limitations in [READ_ADAPTERS](../READ_ADAPTERS.md) are part of this
qualification: isolated-no-filter status semantics; no submodule inspection;
bounded SHA-1/ASCII-ref support; no arbitrary large/linked-special filesystem
support; no atomic snapshot or OS-account-adversary guarantee; in-memory API
attempt accounting; no perfect secret detection or hard total native RAM claim.
A dirty observation never authorizes modifying another agent's worktree.
