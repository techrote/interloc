# IL-005 evidence — private GitHub mailbox transport

## Objective
Implement issue #6's fixed, bounded GitHub transport for one explicitly enrolled private runtime mailbox.

## Inputs/base SHA
Prerequisites IL-002 and IL-003 were merged/evidenced before this branch. Base main SHA: `2e7fe5893ffbc3e507400acb0b791e856d258ee7`. Implementation SHA: `d887d7f64e3a74aea4d939bddc3f6553966d7f70`, PR #43.

## Implemented scope
- Fixed-host `gh api` adapter for `github.com` with only GET/POST/PATCH and fixed headers; callers cannot provide arbitrary gh argv/headers.
- Runtime-mailbox enrollment validation by numeric repository ID, owner/name, private visibility, explicit inbox/outbox branches and device ID.
- Existing gh authentication use without exporting/storing its token; GH/GITHUB token environment variables are not forwarded to the gh subprocess.
- Immutable full-SHA bounded text reads.
- Inbox request discovery by commit history with paging; long/history-gap recovery by complete recursive inbox tree rather than code-search/date-directory assumptions; truncated trees fail closed.
- Atomic outbox publication through blob/tree/commit/non-force ref advancement, with idempotent manifest reuse, collision detection, harmless orphan commits and bounded ref-conflict retry.
- Active/idle poll planning, exponential bounded jitter/backoff, Retry-After handling and a local hourly attempt budget.

## Non-goals
No generic GitHub capability surface, project-repository write capability, screenshot/image upload, browser/Chat automation, public storage, force push, or source-repository-as-runtime-mailbox fallback.

## Security review
No remote bytes can introduce gh arguments, methods outside the fixed set, hostnames or auth headers. Repository identity/private visibility are revalidated. Publication always advances refs non-force. Full-tree discovery refuses truncated results. Remote byte/path limits are enforced before use. Authentication failures and rate limits produce typed failures rather than prompting or credential dumping.
