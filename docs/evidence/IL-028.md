# IL-028 evidence — workflow reconciliation guardrails

## Objective
Implement issue #25's repeatable, idempotent workflow-maintenance tooling without turning the planning auditor into a GitHub credential holder or destructive synchronizer.

## Inputs/base SHA
Prerequisite IL-001 was completed and evidenced before this work began. Branch `codex/il-028-workflow-reconcile` was created from merged main after IL-002 evidence reconciliation. Implementation commit: `2220ccc2c82b666906f61abd8ceb3d5800d8b051`, PR #38.

## Implemented scope
- Read-only reconciliation of a complete issue snapshot against `docs/workflow.json`.
- Canonical identity from stable `<!-- interloc:IL-xxx -->` marker plus manifest issue number.
- Closed `duplicate` issues retained as historical tombstones and explicitly excluded from dependency satisfaction.
- Completion inference only when the canonical issue is `closed/completed` and its declared evidence file exists.
- Required positive gates remain independent of issue state.
- Detection of missing canonical issues, identity mismatch, multiple live stable markers and missing execution sections.
- Deterministic ready-task computation.
- Optional native milestone/label planning as fixed create-only dry-run operations from supplied snapshots; no deletes/renames/overwrites.
- Operator documentation in `docs/WORKFLOW_MAINTENANCE.md`.

## Non-goals
No network calls, GitHub credentials, issue-body rewriting, automatic issue creation/closure, milestone/label mutation, publication of withheld content or inference of runtime success from planning state.

`tools/workflow/`, `tests/workflow/test_reconcile.py`, `docs/WORKFLOW_MAINTENANCE.md`, and this evidence report.

## Native/external checks
Optional native GitHub milestone/label materialization was NOT RUN and is not required for the repository-native workflow. The tool deliberately emits dry-run operations only; any later materialization requires separately authorized exact-target tooling.

## Security review
The implementation has no GitHub/network code and receives no credentials. `issue_mutations` is always empty. Ambiguous identities fail closed rather than auto-repairing. Human issue content is preserved. Duplicate issue tombstones cannot satisfy roadmap dependencies. Native metadata planning never emits delete/update operations.
