# IL-004 evidence — durable broker and crash-aware state machine

## Objective
Implement issue #5's durable request journal, local capability registry, replay protection, bounded admission and crash-aware state machine.

## Inputs/base SHA
Prerequisites IL-002 and IL-003 were merged and evidenced before this branch. Base main SHA: `2e7fe5893ffbc3e507400acb0b791e856d258ee7`. Implementation SHA: `a228b63a2628af28005c4834d8cb95d81cbd6223`, PR #41.

## Implemented scope
- SQLite schema/versioning keyed by `(repository_id, mailbox_epoch, request_id)`.
- Canonical input digest persistence and same-ID/different-digest quarantine/collision evidence.
- Bounded pending admission and durable `rejected`, `awaiting_approval`, `ready`, `running`, `result_saved`, `published`, `notification_pending`, `acknowledged`, `expired`, `cancelled`, `failed`, `indeterminate`, and `quarantined` states.
- Local capability registry with explicit mutating/retry-after-crash attributes.
- Request/policy-decision digest/revision binding at admission/approval.
- Single-owner cross-platform state-root lock.
- Cancellation signal for running work and terminal cancellation/expiry before execution.
- Publication/notification retry state separated from execution so publication retries cannot rerun a capability.
- Restart recovery: only an explicitly registered, non-mutating, locally retryable capability can return from `running` to `ready`; all other interrupted executions become `indeterminate`.

## Security review
Remote request data cannot select Python callables; the registry is local. Mutating capabilities are forbidden from setting automatic crash retry. Same-ID/different-digest requests are quarantined rather than overwritten. Publication references bind only durable results and conflicting publication refs fail closed. Newer unknown DB schemas fail closed.
