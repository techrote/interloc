## Implemented scope

`src/interloc/capabilities/capture/` now provides a locally configured, disabled-by-default Greenshot adapter:

- explicit `CaptureScope` with an opaque UUID and exact allowed process IDs;
- bounded visible-window inventory returning short-lived opaque `window_id` leases;
- leases bind HWND, PID and process-creation time rather than title alone;
- exact identity and foreground-window revalidation before/after capture;
- no activation, focus change, title matching or requester-provided HWND/PID/path/key data;
- strict Greenshot INI validation: non-interactive window capture, `FileDefault` only, PNG, enrolled absolute output directory, clipboard-path copying disabled, and a PrintScreen-based Ctrl/Alt/Shift chord with collision checks;
- Windows `SendInput` limited internally to that validated chord only;
- same-session `Greenshot.exe` process-presence check before any synthetic key input;
- bounded watched-directory snapshot: <=2048 entries, exactly one changed/new regular PNG, no links/junctions, <=10 second timeout and <=16 MiB bytes;
- PNG signature/chunk/CRC/IHDR/IDAT/IEND validation and <=4096 x 4096 dimensions;
- exact SHA-256 and an atomic UUID-named local artifact copy; original Greenshot autosave remains untouched;
- result remains `delivery_state="local_only"`; no publication or model-vision claim.

The provider does not self-register with the broker and does not bypass the unmerged IL-008 local-control path. Runtime composition must still apply the central request/policy/approval journal.

## Security review and interim limitation

The narrow key-input exception is recorded in `docs/SECURITY.md`: remote/request data cannot choose a key or chord, and only the locally read Greenshot PrintScreen-based window chord can be emitted after target/foreground/config checks. The public provider additionally requires a `Greenshot.exe` process in the current Windows session immediately before input.

This process check is not a cryptographic IPC handshake. Greenshot could theoretically exit in the small interval between the presence check and `SendInput`; ordinary OS behavior for the configured PrintScreen chord could then occur. Output timeout/ambiguity prevents Interloc from claiming capture success, but cannot retroactively prevent that possible OS side effect. This race is an explicit limitation of the quick interim integration and a reason to prefer a future direct Greenshot invocation/plugin/IPC or the retained native-capture path if deeper integration is required.

The current Greenshot hook implementation was inspected because it matters to this bridge: matching hotkeys are handled inside Greenshot's keyboard hook before the capture action. Interloc nevertheless treats successful file creation and target revalidation—not mere key delivery—as the capture result.

Use a clean checkout of the exact tested PR head and run the repository's standard install, full `unittest`, CLI smoke and workflow audit.
