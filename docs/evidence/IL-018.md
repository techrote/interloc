## Implemented scope
Explicit local run mappings; bounded regular-file reads; strict metadata/result
validation; complete hash-chain and lifecycle verification; proposed durable
checkpoints; stable event IDs; append/restart/rotation/truncation reporting;
stale-generation and age checks; bounded sanitized evidence via existing helpers.
Unknown schemas and damaged sources produce typed diagnostics with no raw error
or path leakage. Missing installations remain unavailable without bootstrap.

Slot/generation are not present in the producer's per-job metadata. They are
preserved as explicitly operator-mapped values, or null/unavailable, rather than
inventing a verified association. Outcome axes remain source-reported and
`evidence_verified` stays false. The terminal status record outranks its optional
convenience result copy. An isolated `result.json` never establishes success.

## Security review
Only three fixed files in an operator-enrolled run directory can be read. Paths
and source-provided contents do not choose code or commands. Metadata is bound
into the checkpoint; malformed sources never advance it. Hash-chain consistency
is not claimed as source authentication. Persist sanitized evidence before its
checkpoint so interruption repeats evidence rather than silently skipping it.
Same-account OS compromise and caller-owned checkpoint persistence remain explicit
trust/integration boundaries. Truncation and source-reported success stay visible.
