# IL-020 evidence — ordinary-Chat handoff and minimal-client compatibility

## Objective
Determine whether a currently supported lightweight/terminal route can act as a client for ordinary consumer Chat without substituting Codex, Work, or API usage, and decide the `G-assisted` gate for IL-022.

## Inputs/base SHA
Base `main`: `3fe7fc566b10fc7b5dfd2a5cff2f9b24dbafa4d5` (IL-001 merged).
Research performed 2026-09-13 against current OpenAI primary documentation and the product constraints already recorded in this repository.

## Implemented scope
Research/decision only. Re-checked ordinary Chat, Work, Codex, desktop/Classic availability, Codex metering, consumer terms governing automated extraction, and the absence/presence of a documented ordinary-Chat terminal/API surface.

## Non-goals
No DOM automation, browser extension, private endpoint discovery, token/session extraction, output scraping, mode switching, API usage, Codex invocation, or measurement of inaccessible account counters.

## Environment
Documentation review from ordinary Chat. No local/browser automation was executed. No user credentials or conversation output were extracted programmatically.

## Primary sources and findings

1. OpenAI Help, **ChatGPT Work and Codex**, checked 2026-09-13:
   https://help.openai.com/en/articles/20001275
   - Chat is the regular conversational experience; Work is a separate agentic experience; Codex remains a separate software-development view with separate history.
   - Codex is not selectable on web/mobile; ordinary Chat remains available there.

2. OpenAI Help, **Moving to the new ChatGPT desktop app**, checked 2026-09-13:
   https://help.openai.com/en/articles/20001276
   - The supported desktop surfaces are the combined ChatGPT app (Chat/Work/Codex) and the previous `ChatGPT Classic`, which OpenAI says can continue to be used and continues receiving model updates, bug fixes and security patches.
   - This documentation does not describe a terminal/TUI client for ordinary Chat.

3. OpenAI Help, **Using Codex with your ChatGPT plan**, checked 2026-09-13:
   https://help.openai.com/en/articles/11369540
   - Codex CLI is explicitly a Codex client. Signing in with ChatGPT consumes Codex-plan usage rather than turning it into ordinary Chat.

4. OpenAI Help, **Using Credits for Flexible Usage in ChatGPT (Personal plans)**, checked 2026-09-13:
   https://help.openai.com/en/articles/12642688
   - Flexible credits currently apply to Codex/Work and other named agentic features. This reinforces that substituting Codex/Work would violate this project's ordinary-Chat usage boundary.

5. OpenAI **Europe Terms of Use**, applicable to UK users, checked 2026-09-13:
   https://openai.com/policies/eu-terms-of-use/
   - The current terms prohibit automatically or programmatically extracting data or Output and prohibit reverse engineering/bypassing protective measures. Therefore an Interloc route that reads assistant replies by scraping the consumer UI is not approved by this project absent a separately documented supported permission/interface.

## Bounded search result
No current OpenAI primary documentation inspected in this issue documents a CLI/TUI/API that opens or appends messages to an existing ordinary consumer-Chat conversation. This is a bounded current-documentation finding, not a claim that no third-party program exists.

A browser extension/native-messaging mechanism may technically move local data into a browser process, but technical possibility is not evidence of a supported ordinary-Chat transport. No provider-supported route for automated consumer-Chat submission/reply extraction was established here.

## Compatibility matrix

| Route | Ordinary Chat | Avoids Work/Codex allowance | Supported/documented for Interloc automation | Decision |
|---|---|---:|---:|---|
| ChatGPT web/mobile Chat | Yes | Yes | Human UI is supported; programmatic conversation transport not established | Retain human handoff |
| New ChatGPT desktop Chat | Yes | Yes | Human desktop UI supported; no terminal transport established | Optional human surface |
| ChatGPT Classic | Yes | Yes | Supported desktop client; not a terminal client | Plausible lower-complexity human fallback, no automation claim |
| Codex CLI | No (Codex) | No | Supported Codex client | Reject for this requirement |
| OpenAI API | Separate developer/API product | Separate billing/product | Supported API, but not consumer ordinary-Chat history/surface | Reject as substitution |
| Consumer UI DOM/output scraping | Targets Chat UI | N/A | Not established; automated Output extraction conflicts with current individual-use terms | Reject |
| Browser input assistance without output extraction | Potentially | Potentially | No current provider-supported route/interface established | Not qualified |

## Gate decision
`G-assisted = NEGATIVE / NOT QUALIFIED` for the currently investigated routes.

IL-022 MUST NOT be implemented from this evidence. Its published issue remains conditional and should stay open/blocked by its own positive-gate requirement. A future official ordinary-Chat transport or explicit permission could trigger a fresh IL-020 evidence update and a new positive gate; the architecture deliberately leaves that possibility open.

The supported Interloc baseline remains IL-021: prepare a compact immutable evidence pointer and/or reviewed local attachment, then let the human explicitly submit it in the intended ordinary-Chat conversation.

## Security/product review
This result preserves the user's key constraint: no silent Work/Codex/API substitution. It also avoids private endpoint discovery, authentication replay, automated assistant-output extraction, or claiming that DOM access alone constitutes authorization.

## Remaining blockers
No blocker to completing IL-020 itself: a negative research result is explicitly valid under `docs/VERIFY.md` and issue #30.
The negative gate blocks IL-022 implementation until superseded by a documented positive decision.
